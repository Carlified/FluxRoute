mult_2x2 - functional result, 2026-11-03

Function: 2x2 array multiplier, p = a * b (4-bit).
Clocked pads: 4 inputs (a0, a1, b0, b1), 4 outputs (p0, p1, p2, p3).
Target: 3 pipeline levels at 10 GHz
(period 100 ps); input window 35.7..127.2 ps,
chosen centre phase 81.45 ps.

--- from .cir to a viewable, verified waveform ---

Run from the repository root; the folder holding mult_2x2.cir and mult_2x2.tb.json
is the design folder.

  $design = "Win64/Release/output/mult_2x2"    # examples/outputs/mult_2x2 on a checkout
  # run the block, or "cd examples/outputs/mult_2x2" and drop the $design prefix
  # from the file arguments below

1. Read the exported metadata:
     Get-Content $design/mult_2x2.tb.json
   inputs a0, a1, b0, b1   outputs p0, p1, p2, p3
   frequency, pipeline levels, input window and output travel are in this file.

2. Build the stimulus for all 16 patterns and the expected outputs.
   Pattern k assigns a0, a1, b0, b1 to bits 3..0 of k;
   a = a0 + 2 a1, b = b0 + 2 b1, p = a * b, p0..p3 = bits 0..3 of p.
     A0     = 0000000011111111
     A1     = 0000111100001111
     B0     = 0011001100110011
     B1     = 0101010101010101
   expected:
     P0     = 0000000000110011
     P1     = 0000001101010110
     P2     = 0000010100000100
     P3     = 0000000000000001

3. Build, simulate and decode the phase deck:
     python tools/make_tb.py --dir $design `
       --bits "a0=0000000011111111,a1=0000111100001111,b0=0011001100110011,b1=0101010101010101" --slots 16 `
       --run --decode --expect "p0=0000000000110011,p1=0000001101010110,p2=0000010100000100,p3=0000000000000001"
   0.05 ps (39798 points) is stable here.

4. The decode window starts at watch + 1 period (make_tb default):
     clock send  50 ps     data launch 131.45 ps
     watch       289.9 ps  = clock send + 3 periods + travel
     decode      389.9 ps  = watch + 1 period (auto: first capture edge after the data)
     period 100 ps   slots 16   step 0.05 ps
     stop   1989.9 ps (39798 points)

5. Build the I/O-port deck for the same run and look for one pulse per bit
   on every pad:
     python tools/make_tb.py --dir $design `
       --bits "a0=0000000011111111,a1=0000111100001111,b0=0011001100110011,b1=0101010101010101" --slots 16 `
       --io-nodes --out $design/mult_2x2_io_tb.cir --run

6. View the waveforms:
     python tools/josim-plot.py $design/mult_2x2_io_tb.csv -t stacked `
       -x $design/mult_2x2_io_trace.html
   (open mult_2x2_io_trace.html: clock, inputs and outputs as square waves)

--- result ---

All 16 input combinations, decoded twice on the same shared grid:
  phase traces   P(B1|XR<out>): all OK
  pad pulses     V(<out>_o): one pulse per bit, matches the expectation
  input pads     V(<in>_i): read back the stimulus exactly
The die is functionally correct at 10 GHz with the chosen centre phase.

Files:
  mult_2x2_tb.cir/.csv/.meta.json     phase probes
  mult_2x2_io_tb.cir/.csv/.meta.json  I/O port probes
  mult_2x2_io_trace.html              stacked I/O trace (regenerated by step 6)
